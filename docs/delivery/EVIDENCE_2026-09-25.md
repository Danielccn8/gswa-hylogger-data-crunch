All values below were recalculated locally. `data/system` contains the generated
JSON, Parquet, model binaries and dump and is ignored by Git. Historical team
plots are not substituted for these measurements. The original data directory
was read only.

bytes. A further folder (`17BBDD004`) has no compatible file and was recorded
as a failed request in one diagnostic batch. For 05GJD001 SWIR, the source
checksum is `f3079d58fe6de80aadd6034b5f2e660eea90bff0cb78a69d4131872010909cda`:

rows were retained. The product contains 167 bins, 166 with features. Its report
is `data/system/etl/60df8d254d8440036ce3/qc.json`; the mask is explicitly
`unavailable_in_processed_log`.

Extracted TSG-package adjusted spectra were checked separately on 05GJD001 and
LD82625W1 in both SWIR and TIR. Their Final Mask-admitted readings were
18,508/25,938 and 70,717/96,560 respectively. The discarded counts 7,430 and
25,843 were non-rock by that raw-package policy. SWIR has 531 bands, TIR 341;
the corresponding one-metre spectral products contain 166 and 642 intervals.
These counts must not be conflated with the processed interpretation policy.

## Model and spectral checks

Active SWIR model `6f1aca5c44df68fcac93`: k=4, held-out hole YRC10-13,
test silhouette 0.370, mean development seed ARI 0.992. Active TIR model
`66de66eb6381dfdc856a`: k=3, same held-out hole, test silhouette 0.519,
mean seed ARI 0.999. Both cards identify dependencies, schema, transformations,
candidate k values and original-frequency profiles. Their direct-frequency and
PCA comparisons are in `data/system/models/<region>/<model_id>/model_card.json`.

HDBSCAN used a deterministic cap of 80 intervals per development hole (1,990
SWIR; see `data/system/hdbscan_swir.json`). At min cluster size 20 it labelled
28.59% of the sample, leaving 71.41% as noise; at 50 it labelled 68.29% with two
clusters. TIR labelled 20.16% at 20 and 62.57% at 50. The listed silhouettes
exclude noise and therefore reward selective coverage; this comparison did not
replace the active model.

The adjusted-spectrum pilot fits 05GJD001 and infers LD82625W1. SWIR retains
6 PCA components (96.3% development variance), k=2, and flags 585 of 642
inference intervals outside the development distance threshold. TIR retains 8
components (95.8%), k=2, and flags 32 of 642. This large SWIR shift limits
generalisability. The files are `data/system/spectral/<region>/model_card.json`,
`inference.json`, `spectral_view.json` and source hashes in the cards.

50 interval sets. The final dump `data/system/hylogger_26.dump` is 6,427,816 B.
It restored into a separate `hylogger_restore_26` database. Source and restore

IDs remained unchanged after frozen inference.

API responses were checked for `/api/health`, catalogue and coverage, profile,
interval detail, similar intervals, CSV, model cards, batch history and the
spectral pilot. The browser displayed 642 intervals for LD82625W1, its model
explanation, 148–149 m interval detail, a 100-point wavelength chart and
similar intervals. It displayed an empty TIR profile for 07THD003. The CSV URL
uses the visible depth range and active model ID. Browser verification is local;
no human interpretation or GSWA acceptance was performed.

## Reproduction commands actually used

```powershell
docker compose -p hylogger_system -f platform/docker-compose.yml up -d --build
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/run_spectral_pilot.py
.\.venv\Scripts\python.exe scripts/compare_hdbscan.py
.\.venv\Scripts\python.exe platform/etl/run_system.py --data-dir <acquired-data> --holes 05GJD001 --output data/system --mode infer --infer-model-swir 6f1aca5c44df68fcac93 --infer-model-tir 66de66eb6381dfdc856a
docker compose -p hylogger_system -f platform/docker-compose.yml exec -T db pg_dump -U hylogger -d hylogger -Fc -f /tmp/hylogger_26.dump
docker compose -p hylogger_system -f platform/docker-compose.yml exec -T db createdb -U hylogger hylogger_restore_26
docker compose -p hylogger_system -f platform/docker-compose.yml exec -T db pg_restore -U hylogger -d hylogger_restore_26 /tmp/hylogger_26.dump
```

For the batch cohort, `<acquired-data>` was the unmodified original repository's
`data` directory, and `--holes` was the reviewed 26-ID list recorded in
`data/system/benchmark_26_final_console.json`. The benchmark JSON is the
machine-readable source for the table above.
